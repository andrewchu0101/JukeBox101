# 10：容器離線驗證（輔助驗證）

**What to build:** 一個可重現的驗證腳本與證據文件，在無網路、假值設定的條件下驗證容器的關鍵行為：無秘密時安全停止、非 root、SIGTERM 行為、健康檢查分層，以及 Compose 掛載的秘密權限在容器內實際可讀。

**Blocked by:** 09

**Status:** ready-for-agent

**File owner:** `scripts/docker-verify.sh`（新）、`docs/docker-verification.md`（新，記錄實測結果）

## 驗證項目

1. **無秘密啟動**：不提供秘密時，容器以非零退出碼結束，訊息不含秘密。
2. **無網路登入失敗**：提供假值秘密並以無網路模式執行，程序應在登入階段失敗（證明未連到 Discord），且不輸出假值。
3. **非 root**：容器內程序的有效使用者不為 root。
4. **SIGTERM**：收到停止信號後，程序在時限內結束，退出碼可辨識。
5. **健康檢查分層**：容器存活、設定載入、Discord 連線三層能分別回報；本票只驗證前兩層，第三層在無網路時應回報「未連線」而非「健康」。
6. **掛載權限實測**：以 Compose 實際掛載秘密檔案，檢查容器內的擁有者、群組與權限，確認 02 的場景 B 判定結果與預期一致。同時記錄 Compose 版本與是否忽略 uid、gid、mode 屬性。
7. **資源限制**：確認 CPU 與記憶體限制在容器內實際生效（可由容器內讀取限制值確認）。

## 注意

- 驗證時不得使用真實 Token 或真實資料庫密碼；一律使用明確假值，並標示為假值。
- 不得修改正式入口使其繞過 fail-closed 或偽裝健康。
- 本票不連線正式 Discord 或 MySQL。

**TDD 驗證：** 腳本本身的失敗路徑（例如映像不存在、秘密未提供）必須先以測試證明會回報明確錯誤，再實作成功路徑。

**Acceptance criteria:**
- [ ] 上述 1 至 7 項各有通過、失敗或未執行的明確結果，附實際命令與退出碼。
- [ ] 證據文件不含任何秘密值，只記錄「假值」與結果。
- [ ] 區分「離線容器驗證通過」與「正式 Bot 連線可用」，文件中明確標示後者未驗證。
- [ ] 若某項無法在本機執行，標示為略過並說明原因，不宣稱通過。

**Out of scope:** 正式 Discord 連線（見 15）。
