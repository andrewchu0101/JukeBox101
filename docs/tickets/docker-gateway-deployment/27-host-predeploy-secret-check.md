# 27：主機來源秘密檔案的部署前檢查腳本

**What to build:** 夥伴在部署時執行的檢查腳本。它驗證主機上的秘密來源檔案的擁有者、指定群組與權限，失敗時輸出不含秘密的修復說明。它不讀取或輸出秘密內容，不自行 chmod、chown 或提權。

**Blocked by:** 02（判定規則已完成）

**Status:** ready-for-agent

**Single owner:** `secret-config-dev`（同一人負責 `bot/secret_file_policy.py`，避免判定規則分裂）

**File owner:** `scripts/deploy/check-host-secrets.sh`（新）、`tests/test_host_secret_check.py`（新）

## 分工

- Owner：配置秘密與預期擁有者、群組（由 Owner 提供，不寫死本機帳號）。
- 夥伴：部署時執行本腳本，依輸出的修復說明處理。
- 容器內掛載檔仍由程式獨立驗證（工單 03），**不得以主機檢查取代**。

## 行為要求

- 只讀取檔案的擁有者、群組與權限位元，不開啟檔案內容。
- 預期擁有者與群組必須由參數或環境變數明確提供；未提供即失敗，不得以預設值通過。
- 判定規則沿用工單 02 的場景 A（主機來源檔）：其他人有任何位元拒絕、群組寫入拒絕、非指定群組讀取拒絕、擁有者不符拒絕。
- 失敗時輸出修復說明：列出目前的數字擁有者、群組與權限，以及預期值，並給出修復指令範本（不自動執行）。
- 不輸出檔案內容、長度、雜湊或任何秘密值。
- 不需要 root；若需要提權才能讀取，回報權限不足並停止，不得自行提權。

## TDD 驗證（紅→綠）

- 紅：未提供預期擁有者或群組 → 失敗，訊息說明缺少設定。
- 紅：其他人可讀 → 失敗，修復說明含目前與預期值。
- 紅：群組可讀但非指定群組 → 失敗（`GROUP_READ_UNDEDICATED`），修復說明明確指出群組不符。
- 紅：擁有者不符 → 失敗。
- 紅：0400 或 0440（指定群組）且擁有者正確 → 通過。
- 紅：輸出不含測試用假秘密內容。
- 紅：腳本不呼叫 chmod、chown（以靜態檢查與替身驗證）。

**Acceptance criteria:**
- [ ] 失敗的每一種情況都有清楚、不含秘密的修復說明。
- [ ] 不自動修改檔案權限或擁有者。
- [ ] 容器內掛載檔的獨立驗證仍保留在程式中。
- [ ] 測試以 Python 3.12 執行，列出通過、失敗、略過數量。
