# 04：正式 Gateway 入口接入 Owner 審核指令，並驗證權限

**What to build:** 正式入口建立 Discord 用戶端時，傳入與 Owner 命令列工具使用同一類型審核儲存庫的 Owner 審核接線。結果是：在私人伺服器中，只有 Owner 能看到並使用 `/owner` 群組；其他人或其他伺服器得到相同拒絕訊息。

**Blocked by:** 03（同一個入口檔案，需依序修改）

**Status:** ready-for-agent

**File owner:** `bot/__main__.py`（在 03 完成之後）、`tests/test_gateway_entry_owner_wiring.py`（新）

**現況依據：** 正式入口目前沒有傳入 Owner 接線，因此 `/owner` 不會被註冊。既有測試已示範接線的寫法（以替身服務建立用戶端並檢查指令樹），可作為先例。

**TDD 驗證：**
- 紅：正式入口建立的用戶端，指令樹中包含 `/owner` 群組，且只限定設定的私人伺服器。
- 紅：非 Owner 使用者呼叫 `/owner` 時，得到與「錯誤伺服器」相同的拒絕訊息。
- 紅：Owner 在錯誤伺服器呼叫時，得到相同拒絕訊息。
- 紅：預覽過期後確認，不呼叫寫入服務。
- 紅：預覽後案件版本已變更，確認被拒絕，不寫入。
- 綠後重構：Owner 身分與伺服器 ID 只從一個設定來源讀取。

**Acceptance criteria:**
- [ ] 正式入口註冊 `/owner`，範圍限定於設定的私人伺服器。
- [ ] 非 Owner 與錯誤伺服器得到相同拒絕，不洩漏原因。
- [ ] 寫入前必須有預覽與確認，確認一次性，過期與版本變更被拒絕。
- [ ] 審核儲存庫類型與 Owner 命令列工具一致，不新增另一個寫入路徑。
- [ ] 測試使用替身，不連線 Discord 或 MySQL。
- [ ] 離線測試以 Python 3.12 執行通過，並列出通過、失敗、略過數量。

**Out of scope:** 真實 Discord 指令同步與真實寫入（見 15，需另行授權）。

**待實作時核對：** Owner 審核儲存庫在正式入口的建立方式是否需要新的資料庫帳號權限（需與 Bot 專用帳號規格比對，若需要更多權限則回報，不自行擴大）。
