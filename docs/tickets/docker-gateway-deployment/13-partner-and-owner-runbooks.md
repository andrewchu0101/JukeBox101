# 13：夥伴部署與更新文件、擁有者秘密配置與輪替文件

**What to build:** 兩份分開的文件，以及對既有 HTTP 部署文件的標示。夥伴文件說明部署、更新、回滾與健康檢查；擁有者文件說明秘密配置、權限、輪替與備份。

**Blocked by:** 11、12

**Status:** ready-for-agent（秘密傳輸方式、實際路徑與備份責任人需 Owner 確認；文件以可設定的佔位符保留）

**File owner:** `docs/deploy/partner-deployment.md`（新）、`docs/deploy/owner-secrets.md`（新）、`deploy/RUNBOOK.md`（僅在最上方加入「未採用的 HTTP 候選方案」標示，內文不動）

## 夥伴文件必須包含

前置需求（Docker、Compose、Linux amd64）、取得交付包與 SHA-256 核對、建置、啟動（不含秘密時的預期停止）、健康檢查（說明三層的實際驗證範圍）、日誌（不含秘密）、停止、更新（沿用既有秘密）、回滾到上一版映像、資料備份的責任界線。

**權限邊界聲明（必須）：** 夥伴若擁有主機管理員或完整 Docker 權限，技術上可以讀取容器使用的秘密。Docker secrets 不保證對主機管理員保密，也不是自動加密保管庫。

## 擁有者文件必須包含

建立 Bot 專用與維護帳號的步驟（不含真實帳密）、秘密檔案的建立、放置路徑（佔位符，待確認）、擁有者與權限設定（依 02 的規則）、首次交付前的檢查、輪替步驟與生效方式（需重建或重啟容器）、洩漏時的處置、備份責任人與範圍（待確認）、秘密傳輸方式（待確認）。

## 待確認項目（不阻擋撰寫，但文件必須標示）

- 秘密傳輸管道。
- 主機實際秘密路徑。
- 備份責任人與範圍。

## TDD 驗證

- 紅：夥伴文件不含真實秘密樣式（靜態掃描）。
- 紅：夥伴文件不要求夥伴填寫真實秘密。
- 紅：`deploy/RUNBOOK.md` 在最上方含「未採用」標示，且其餘內容與原本逐字相同（以比對驗證）。
- 紅：兩份文件的指令與工作票 10、11 的驗證結果一致（逐項比對）。

- [ ] 所有待確認項目以明確標示，不假設答案。
- [ ] `deploy/RUNBOOK.md` 只增加標示，不改動其餘內容。
- [ ] 文件不宣稱正式部署已完成。

**Out of scope:** 實際在夥伴主機上執行部署（見 15）。
