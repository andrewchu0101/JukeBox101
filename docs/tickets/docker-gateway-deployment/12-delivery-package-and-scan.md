# 12：精簡交付包、解壓複查與機敏掃描

**What to build:** 一個可重現的打包腳本，依允許清單產生精簡交付包；另一個掃描腳本，對工作樹、映像與交付包（解壓後）進行機敏掃描，並輸出 SHA-256。

**Blocked by:** 09、11

**Status:** ready-for-agent

**File owner:** `scripts/delivery/build-package.sh`（新）、`scripts/delivery/scan-package.sh`（新）

## 允許清單（需包含）

實際必要程式、Dockerfile、`.dockerignore`、Compose 設定、依賴鎖定、假值設定範例、部署文件、必要 SQL 資源與授權資訊。

## 排除（必須）

`.env`、`.local/`、`.git/`、私人驗收證據、真實憑證、資料庫 dump 或 volume、虛擬環境、快取、日誌、測試證據目錄、既有 `deploy/` 中未採用的 HTTP 模板以外的私人檔案。

## 掃描要求

- 掃描來源：工作樹、交付包解壓後的每個檔案、映像的每一層與建置中繼資料（後者由 09 的建置產出提供）。
- 使用可用的秘密掃描工具（若本機沒有，記錄為缺口，不宣稱零風險）；另加人工規則（例如 Token 形狀、Webhook URL、私鑰標頭、密碼賦值）。
- 報告只列遮罩結果與位置，不輸出秘密內容。
- 掃描壓縮包的路徑，檢查是否有絕對路徑、路徑穿越或不允許的檔案。
- Git 歷史掃描需獨立記錄；若發現疑似外洩，列為阻擋項，不自行重寫歷史或更換線上憑證。

## TDD 驗證

- 紅：打包腳本對含假秘密的測試檔案會拒絕產生交付包（使用測試資料夾，不使用真實資料）。
- 紅：排除清單中的檔案不會進入交付包。
- 紅：解壓後的檔案清單與允許清單一致。
- 紅：SHA-256 與實際檔案一致。

**Acceptance criteria:**
- [ ] 交付包依允許清單產生，且可重現（相同輸入產生相同清單）。
- [ ] 解壓後複查與掃描通過，並記錄工具版本與缺口。
- [ ] 提供 SHA-256。
- [ ] 不把 heuristic 掃描結果當成零風險結論。
- [ ] 不把映像或私人證據放入交付包。

**Out of scope:** 發布或傳送交付包。
