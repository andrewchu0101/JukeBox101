# 08：開發者從本機安全查看資料庫的文件

**What to build:** 一份文件，說明開發者如何在不暴露 3306 的前提下，以唯讀帳號查詢資料，並區分三類帳號的用途與權限。文件本身不含任何真實帳密。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**File owner:** `docs/database-access.md`（新）

## 文件必須包含

1. **三類帳號比較**：唯讀查詢帳號、Bot 執行帳號、維護帳號，各自的用途、權限範圍與存取位置。
2. **唯讀查詢帳號**：只授予查詢權限；連線後以唯讀 session 開啟（與既有唯讀檢查的做法一致）；禁止在查詢工具中執行寫入語句。
3. **存取方式**：經 SSH 隧道或主機內部連線，不開放 3306 到公網；說明如何在本機建立隧道（使用佔位符，不含真實主機）。
4. **帳號建立責任**：由 Owner 依文件建立，程式不自動建立帳號。
5. **Bot 執行帳號**：只由 Bot 容器使用，權限為應用程式所需最小集合。
6. **維護帳號**：只在 Migration 或結構維護時由 Owner 使用，不放入 Bot 容器。
7. **禁止事項**：不得以 root 或管理員帳號查詢；不得把帳密寫入文件、程式或交付包；不得直接修改餘額（見 07 與規格的 Nickel 一致性規則）。
8. **查詢範例**：只提供唯讀查詢範例，不含寫入範例。

**Acceptance criteria:**
- [ ] 文件清楚區分三類帳號，且每類都有明確的存取範圍。
- [ ] 文件不含真實帳密、主機位址或 IP；全部使用佔位符。
- [ ] 文件說明 3306 不對公網開放。
- [ ] 文件說明禁止以直接改表補發 Nickel。
- [ ] 文件經人工審閱；本票不包含連線測試。

**Out of scope:** 實際建立資料庫帳號（Owner 在正式部署前執行，見 13）。
