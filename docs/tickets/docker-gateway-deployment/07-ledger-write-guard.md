# 07：帳本寫入守衛（輔助驗證）

**What to build:** 一組離線測試，驗證既有交易與帳本一致性：每個已核准的餘額寫入點都在同一交易內同時寫入帳本與餘額快取；帳本完整性檢查能偵測不一致。新增未經核准的寫入點時測試失敗。

**範圍界線（Owner 已確認）：**
- 只驗證「既有」交易與帳本一致性。
- 不新增人工調帳、補發或扣除指令。
- 不修改結算規則。
- 若發現實際缺陷，先提出具體證據（重現步驟與離線測試失敗輸出），再提出最小修補範圍；不藉此重構帳務系統。修補需 Owner 核准後才實作。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**File owner:** `tests/test_ledger_write_guard.py`（新）。本票不修改程式碼；若發現違規寫入點，回報並另開票，不在本票中修正。

**現況依據：** 目前所有餘額變動都是成對寫入（帳本列與餘額快取在同一交易內）。本票把這個事實轉成可執行的守衛。

**TDD 驗證：**
- 紅：列出所有修改餘額快取的寫入點，與已核准清單完全相同。任何新增的寫入點都使測試失敗。
- 紅：每個核准寫入點都同時寫入帳本。
- 紅：帳本完整性檢查能偵測直接改表造成的不一致（以替身資料驗證）。
- 紅：不存在「手動調整 Nickel」的 Owner 指令。

**Acceptance criteria:**
- [ ] 核准的餘額寫入點清單以常數記錄，變動需要修改測試並經審查。
- [ ] 直接改表不一致可被完整性檢查偵測。
- [ ] 不新增任何 Owner 手動 Nickel 指令。
- [ ] 離線測試以 Python 3.12 執行通過，並列出通過、失敗、略過數量。
- [ ] 不連線 MySQL；使用靜態掃描與替身資料。

**Out of scope:** 修正既有程式；補償流程的真實驗收。
