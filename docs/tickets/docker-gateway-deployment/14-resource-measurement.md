# 14：資源量測與容量假設

**What to build:** 一份量測文件，記錄映像大小（本機展開與壓縮傳輸大小分開）、建置時間、閒置與代表性離線負載下的 CPU 與記憶體，並說明頻寬估計的假設與限制。

**Blocked by:** 10、11

**Status:** ready-for-agent

**File owner:** `docs/resource-measurement.md`（新）

## 量測要求

- 目標主機規格（2 vCPU、8 GB RAM、100 GB SSD、8 TB 月傳輸、1 Gbps）作為假設，明確標示「未在該主機上實測」。
- 閒置量測：至少記錄一段固定時間的 CPU 與記憶體平均與峰值，並說明量測期間與方法。
- 離線代表性負載：以替身或離線腳本模擬，不連線正式 Discord；說明負載的定義。
- 映像大小：本機展開大小與壓縮傳輸大小分開記錄。
- 建置時間：記錄環境與命令。
- 頻寬：以假設的 Discord 與 MySQL 流量估計，並標示未驗證部分。

## 注意

- 不承諾零 CPU 或零流量。
- 不以不同條件或短時間觀察宣稱長期穩定。
- 不把 Docker Desktop 的 WSL 量測當成目標主機的結果。

**TDD 驗證：** 量測腳本的輸出格式先以替身資料測試（欄位完整、單位明確），再進行實際量測。

**Acceptance criteria:**
- [ ] 所有數字都附量測環境、期間與方法。
- [ ] 目標主機數字與本機量測分開標示。
- [ ] 未量測項目明確列為「未驗證」。
- [ ] 不宣稱支援的負載範圍，除非有實際量測支撐。

**Out of scope:** 在目標主機上實測（需 Owner 授權與主機存取）。
