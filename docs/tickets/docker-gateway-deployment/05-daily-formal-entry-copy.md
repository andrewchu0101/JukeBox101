# 05：正式入口 `/daily` 的指令說明與行為對齊

**What to build:** 正式入口的 `/daily` 指令說明與實際行為一致。實際行為是：在正式入口（已設定提交儲存庫）下，**不保存偏好、不發送 DM**，只回覆固定說明。

**Blocked by:** None（程式行為已確認），但「指令說明文字」需 Owner 核准後才能修改（見「待 Owner 核准」）。

**Status:** needs-owner-copy-approval

**File owner:** `bot/discord_app.py`（僅 `/daily` 的描述字串）、`tests/test_daily_formal_entry.py`（新）

## 已核對的行為

- 正式入口建立服務時會提供提交儲存庫，因此 `daily` 方法在第一行判斷後直接回覆「私人 Beta 尚未開放每日推薦；本次未保存偏好，也不會發送 DM。」，不會呼叫保存偏好的方法。
- 「已開啟／已關閉偏好」的分支只在沒有提交儲存庫時才會執行，正式入口不會進入。
- 目前的指令說明寫的是「設定每日推薦偏好（排程尚未啟用）」，容易讓使用者誤以為會保存偏好，與實際行為不符。

## TDD 驗證

- 紅：正式入口下執行 `/daily on`，偏好保存方法未被呼叫。
- 紅：正式入口下執行 `/daily off`，偏好保存方法未被呼叫。
- 紅：回覆文字與規格一致，且包含「未保存偏好」與「不會發送 DM」的含義。
- 紅：指令說明不含「設定」等暗示已保存的字樣（待核准後的新文字）。
