# 離線資源量測（替身負載）

**性質聲明：本文件所有數字都是「離線替身負載」下的結果，不是正式 Discord 運行效能。** 登入、Gateway 連線與資料庫都以替身取代，沒有真實的 Discord 事件量，也沒有真實的 MySQL 往返延遲。不得把這些數字當成正式環境的 CPU 或記憶體預估。

## 量測日期與環境

- 量測日期：2026-10-29（本機時間）。
- 作業系統：WSL2（Linux 6.18.54.1-microsoft-standard-WSL2）。
- CPU：12 核心；記憶體：約 7.8 GiB 總量，量測時約 2.9 GiB 可用。
- Python：3.12.15，專案虛擬環境 `/home/gaston/.venvs/jukebox101-py312`，discord.py 2.7.1。
- 沒有連線正式 Discord 或正式 MySQL，沒有使用正式秘密。

## 量測對象與方法

- 程序：以真正的 `bot.__main__.main()` 在子程序中啟動，包含設定讀取、Owner 審核接線與 `JukeBoxClient` 建立。
- 替身：
  - `discord.Client.start` 以替身取代：記錄 `LOGIN_STARTED` 後不再連線，只執行指定的離線負載。
  - `discord.Client.close` 以替身取代，不做網路動作。
  - `pymysql.connect` 以替身取代，若被呼叫就失敗。
- 取樣：父程序每秒讀取 `/proc/<pid>/stat`（utime + stime，換算為 CPU 百分比）與 `/proc/<pid>/status`（VmRSS、VmHWM）。
- 期間：每個情境各 30 秒，從 `LOGIN_STARTED` 之後開始計時。

## 情境與結果

| 情境 | 離線替身負載 | 時長 | CPU 平均（單核心比例） | RSS 最後值 | RSS 最大值（VmHWM） |
| --- | --- | --- | --- | --- | --- |
| 閒置 | 只等待，每秒醒來一次 | 30 s | 0.00 % | 48,960 KiB（約 47.8 MiB） | 48,960 KiB |
| 代表性離線負載 | 迴圈呼叫 `bot.urls.parse_youtube_url` 處理 3 種合成 URL（短連結、含追蹤參數的連結、非 YouTube 連結），每輪之間讓出事件迴圈 | 30 s | 99.86 %（約一個核心滿載） | 48,872 KiB（約 47.7 MiB） | 48,872 KiB |

觀察：
- 閒置時 CPU 接近 0，RSS 穩定在約 48 MiB，30 秒內沒有增長。
- 解析負載會讓單一核心滿載，但 RSS 沒有增長，表示這段負載沒有累積記憶體。
- 解析負載的吞吐量（每秒處理幾筆 URL）沒有記錄，因此這個數字無法換算成正式的 `/share` 速率。

## 限制

1. 負載是人為設計的單執行緒迴圈，不代表真實的 Discord 事件分佈，也不包含 MySQL 查詢、交易與 `asyncio.to_thread` 的執行緒切換成本。
2. 只量測 30 秒，沒有長時間穩定性數據，不能推論數小時或數天的記憶體趨勢。
3. WSL2 的 `/proc` 數值來自 Linux 核心的 WSL 實作，與 Windows 原生或容器內的數值不一定一致。
4. 沒有量測 SIGTERM 收到後的關閉耗時；關閉行為只由測試覆蓋（見下）。
5. 未量測磁碟、網路與檔案描述元用量。

## 關閉行為的相關驗證（與量測分開）

`tests/test_lifecycle_sigterm.py` 以子程序啟動正式入口，驗證：無進行中工作時 SIGTERM 後 Discord 用戶端 `close` 被呼叫一次並以 0 結束；進行中工作在期限內完成時以 0 結束；超過期限的工作被取消並以 3（SHUTDOWN_INCOMPLETE_EXIT_CODE）結束並回報「仍在執行」；執行緒中的資料庫呼叫超過期限時回報資料庫工作可能未完成，且程序不等待執行緒；清理步驟失敗以 1（SHUTDOWN_FAILED_EXIT_CODE）結束，只輸出步驟名稱與例外類別。測試中的期限為 2 秒（模組屬性），正式期限為 20 秒。這些測試不是效能數據。

## 未驗證事項

- 真實 Discord Gateway 的長時間連線與重連行為。
- 進行中的資料庫交易在 SIGTERM 時的實際結果：寬限期內完成的交易會正常結束；超過期限者無法強制中止執行緒內的資料庫呼叫，程序以 3 結束並回報「資料庫工作可能未完成」，未提交的交易由 MySQL 在連線中斷時回滾，結果不明的交易依既有恢復紀錄處理。這些情況只在離線替身中驗證。
- 正式部署環境（容器、資源上限）下的 CPU 與記憶體。
